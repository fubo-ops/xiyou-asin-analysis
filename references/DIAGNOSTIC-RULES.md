# 诊断与证据规则

## 何时读取

快速体检、定向深挖、写结论、评审动作和 7/14/30 天复盘时读取。

## 总原则

先判断数据能回答什么，再判断指标发生什么，最后才讨论原因。找“最早可确认的断点”，不得因下游数据缺失把原因写成事实。

## 漏斗链

### 覆盖

目的：判断自身是否进入了目标查询集合。

- 查询词池：精确 Case 周期内，西柚关键词明细中的唯一关键词数。
- 自身覆盖：自身有自然排名、SP 广告排名或正流量份额的查询数。
- 竞品覆盖而自身缺失：至少一个竞品覆盖且自身不覆盖的查询数。
- 该阶段数据是 L3 估算，只能说“西柚观测到的覆盖差距”。

### 排名

目的：在已覆盖查询里判断自身是否落后。

- 自身自然排名查询数。
- 自身自然 Top 10 / Top 20 查询数。
- 同词落后最优竞品的查询数。
- 不能把自然排名差距直接归因于广告、价格或 Listing。

### 点击

目的：判断获得曝光/排名后是否形成点击。

首选 SQP 的 `asinClickCount ÷ asinImpressionCount`，按同一周、同一 ASIN、同一查询汇总。若 SQP 缺失，只能展示西柚排名与正份额代理，不输出真实 CTR。

定向补数可包括主图、标题、图片、视频、A+、QA、价格和评论快照。快照只能支持同一采集时点的页面对比。

### 转化

目的：判断点击或 Sessions 是否形成购买。

- Sales and Traffic：`units_ordered ÷ sessions`，官方经营事实。
- SQP：`asinPurchaseCount ÷ asinClickCount`，查询词级官方事实。
- 无 Ads API 时不输出广告 CVR、ACOS、TACOS。
- 西柚估算订单不能替代后台订单。

## 定向深挖选择

| 最早断点 | 只补什么 | 不应先补什么 |
|---|---|---|
| 覆盖 | 关键词 Gap、相关性、竞品独占词 | 全量评论语义、广告花费 |
| 排名 | 同词位次、自然/广告位置、趋势 | 无关关键词的 Listing 重写 |
| 点击 | SQP、主图/标题/价格/Rating 快照 | 先假定是 CVR 问题 |
| 转化 | SQP、Sales and Traffic、评论痛点、价格/Coupon | 用西柚估算代替后台事实 |

## 置信度

| 级别 | 条件 | 允许措辞 |
|---|---|---|
| 高 | 两个独立来源一致，且至少一个 L1/L2 | “证据支持…” |
| 中 | 一个 L1/L2 来源，或两个独立 L3 来源 | “当前数据表明…” |
| 低 | 单一 L3、代理指标或周期不完全一致 | “西柚估算提示…，待验证” |
| 不可验证 | 缺权限、缺周期、字段空、来源冲突 | “当前无法验证” |

来源独立是指不同生成机制；同一 XLSX 的两个单元格不是两个独立来源，同一 API 报告的两个版本也不是两个独立来源。

## 发现、原因、动作

每条建议必须具备：

1. 发现：具体指标、周期、对象与 Evidence ID。
2. 原因：已验证原因或明确标成假设，附第二来源。
3. 动作：具体改什么、负责人、风险、开始条件、停止条件。
4. 验证：7/14/30 天指标、基线、目标和同口径数据源。

动作不得由本 Skill 自动执行。人工门②必须选择、修改或拒绝动作。

## 数据质量门

- G0 范围：站点、ASIN、周期、目标明确。
- G1 周期：参与计算的数据周期一致或差异已披露。
- G2 竞品：竞品集合经人工门①确认。
- G3 来源：关键漏斗阶段有可用来源；缺失阶段明确降级。
- G4 事件：断货、Deal、Coupon、调价、变体变化已确认或列为待验证。
- G5 公式：比率按统一分子/分母重算，不对百分比求和。
- G6 追溯：每个数字有唯一 Evidence ID、locator 和可读取原始文件。
- G7 结论：强结论至少两个独立来源，低置信度不冒充事实。

任一关键门未通过，报告状态只能是 `REVIEW_REQUIRED` 或 `BLOCKED`，不能写“分析完成”。

## 版本采用规则

### Sales and Traffic

- 同一周期的所有下载均保留。
- 不覆盖、不删除、不跨版本相加。
- 默认采用 `captured_at` 最新的完整可解析版本。
- 报告写明保留版本数和采用的 Artifact ID。
- 若不同版本差异影响结论，标记来源冲突并请求人工复核。

### 西柚

- 下载按钮触发不等于文件成功落盘。
- 以最终文件可打开、大小合理、SHA-256 已登记为成功。
- 内容相同的重复导出可语义去重，但原始 Artifact 仍保留。
- 不同时间档位分别登记并按 Case 精确匹配；不拼接成虚假的长周期。

### SQP

- 创建后立即持久化 `reportId`。
- `IN_QUEUE`、`IN_PROGRESS` 或轮询超时后恢复同一 `reportId`。
- 只有明确终态且无可恢复 ID 时，才讨论重新创建；必须人工确认。
- `AVAILABLE_EMPTY` 是“可下载但空”，不是零值。
- 部分完整周可标 `PARTIAL_AVAILABLE`，并披露覆盖周数。

## 冲突处理

- Amazon L1 与西柚 L3 冲突：经营事实采用 Amazon；西柚只作为估算差异说明。
- 西柚页面与导出冲突：保留两者采集时点；结构化计算优先官方导出，页面仅作快照证据。
- 商品前台与 Seller Central 冲突：披露时点与视角差异，不自行判断库存、Coupon 或变体事件。
- 字段语义不明：保留原始字段，加入 open questions，不映射到已有指标。

## 复盘口径

- 7 天：检查动作是否部署、覆盖/排名是否有方向变化。
- 14 天：检查点击或转化是否出现稳定信号。
- 30 天：用同一站点、ASIN 集合、时间档位和公式重新体检。
- 竞品集合、价格环境或变体结构发生变化时，建立新 run 并披露不可直接横比项。
